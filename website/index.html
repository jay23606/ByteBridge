ByteBridge

واجهة HTTP صغيرة محمية بمفتاح أمام قواعد بياناتك، تصل إليها من خارج الجهاز عبر نفق مثل Cloudflare Tunnel، دون أن تكشف منفذ قاعدة البيانات أو تغيّر إعدادات الراوتر.

يعمل على Windows خدمةً مع لوحة تحكم، وعلى Linux خدمةَ systemd تديرها من الطرفية. أضف اتصالات قواعد بياناتك، واجعل ما تريده منها متصلاً، فتقدّمها البوابة بصيغة JSON على العنوان 127.0.0.1.

الميزات

يعمل خدمةً في الخلفية

خدمة Windows باسم ByteBridge، أو وحدة systemd باسم bytebridge. تبدأ مع تشغيل الجهاز وتخدم دون أن يسجّل أحد الدخول، فإغلاق النافذة لا يوقف البوابة.

محرّكان لقواعد البيانات

Firebird 4 (المنفذ الافتراضي 3050) وPostgreSQL (المنفذ 5432)، وكلاهما مختبَر على خادم حقيقي في CI.

للقراءة فقط افتراضياً

لا يقبل /query إلا SELECT أو WITH، ويشغّله في معاملة يجعلها محرّك قاعدة البيانات نفسه للقراءة فقط. وتبقى الكتابة عبر /execute متوقفة حتى يفعّل مسؤول خيارات ← السماح بالكتابة.

مفتاح API مع كل طلب

32 بايتاً عشوائية تُولَّد عند أول تشغيل وتُقارَن بزمن ثابت. يبدّله زر مفتاح جديد دون إعادة تشغيل، ومن يرسل مفاتيح خاطئة كثيرة يُرفض بالرمز 429 لفترة.

أسرار مشفّرة على القرص

كلمات سر قواعد البيانات ومفتاح API مشفّرة بمفتاح لا يغادر الجهاز ويُحفظ خارج مجلد البيانات: DPAPI على Windows، وملف مفتاح لا يقرؤه إلا مالكه على Linux. نسخة من مجلد البيانات وحدها لا تفتح شيئاً.

سجل لكل طلب

يُضاف كل طلب إلى سجل الطلبات، سواء خُدم أو رُفض. تُكتب العبارة نفسها، ولا تُكتب قيم المعاملات أبداً.

تحديثات بموافقتك

يسأل GitHub عن إصدار أحدث مرة يومياً تقريباً ويعرض شريطاً في لوحة التحكم. يتحقق حدّث الآن من ملف التثبيت مقابل checksums الإصدار، ولا يشغّله إلا بعد موافقتك. وعلى Linux يتولى apt التحديث.

Cloudflare Access عند الحاجة

ضع Cloudflare Access أمام اسم النطاق لتُصادَق الطلبات على شبكة Cloudflare قبل أن تصل إلى جهازك. وإن أعددت تسجيل الدخول عبر Cloudflare في ByteBridge، فالجلسة الصالحة منه تُقبل بدل المفتاح.

نفق جاهز عند الحاجة

اختر الاتصال بـ ByteBalance من النافذة، أو نفّذ enroll من سطر الأوامر، لتُنشئ ByteBalanceTech النفق لك. ByteBridge منتج مستقل، وهذا التكامل اختياري.

التثبيت

يتطلب Windows 8.1 أو أحدث بنسخة 64 بت، أو توزيعة Linux بنسخة 64 بت مع systemd، إضافة إلى خادم Firebird 4 أو PostgreSQL يتصل به.

Windows

نزّل ملف التثبيت من أحدث إصدار. كل ملفات التثبيت تثبّت البرنامج للجهاز كله، وتطلب صلاحيات المسؤول مرة واحدة.

الملف‎.NETمتى تستخدمه
…-x64-setup.exeمضمَّنابدأ من هنا. تثبيت عادي على جهاز مكتبي.
…-x64.msiمضمَّنGroup Policy أو Intune أو نشر آلي بسكربت.
…-x64-framework-setup.exeيُنزَّلحجم أصغر بكثير؛ يثبّت برنامج الإعداد بيئة التشغيل إن لم تكن موجودة.
…-x64-framework.msiمطلوبنشر آلي تُدار فيه بيئة التشغيل بشكل منفصل.

يعرض ملفا .exe أيضاً تثبيت cloudflared. أما ربطه بنفق فيحتاج إلى رمز النفق الخاص بك.

التثبيت الصامت:

ByteBridge-<version>-x64-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART
msiexec /i ByteBridge-<version>-x64.msi /quiet /norestart

Linux (Debian وUbuntu)

أضف مستودع apt الموقَّع مرة واحدة، وبعدها يتولى apt install وapt upgrade الباقي.

sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://kenanwahbeh.github.io/ByteBridge/bytebridge.asc | sudo tee /etc/apt/keyrings/bytebridge.asc >/dev/null
echo "deb [arch=amd64 signed-by=/etc/apt/keyrings/bytebridge.asc] https://kenanwahbeh.github.io/ByteBridge stable main" | sudo tee /etc/apt/sources.list.d/bytebridge.list
sudo apt update
sudo apt install bytebridge

بصمة مفتاح التوقيع موجودة في صفحة مستودع apt؛ قارنها بناتج gpg --show-keys /etc/apt/keyrings/bytebridge.asc.

للتوزيعات الأخرى: يتضمن كل إصدار ملفاً مضغوطاً linux-x64 فيه install.sh، وملف .deb نفسه، مع checksums في SHA256SUMS-linux.txt. التفاصيل في دليل Linux (بالإنكليزية).

تحقّق من مصدر الملف

يحمل كل ملف في الإصدار شهادة بناء موقَّعة تبيّن أين بُني، وتتحقق منها أداة GitHub CLI قبل أن تشغّل أي شيء:

gh attestation verify ByteBridge-<version>-x64-setup.exe --repo kenanwahbeh/ByteBridge

البداية السريعة

لست مطوّراً؟ يشرح الدليل المصوَّر الخطوات نفسها بالصور. ومن داخل البرنامج يفتحه تعليمات ← دليل الاستخدام (أو المفتاح F1).

  1. أضف قاعدة بيانات

    اختر ملف ← قاعدة بيانات جديدة...، واملأ الخادم والمنفذ واسم المستخدم وكلمة السر ومسار قاعدة البيانات أو اسمها المستعار، ثم اضغط اختبار الاتصال قبل الحفظ. على Linux استخدم bytebridge db add.

  2. تأكّد أنها متصلة

    الاتصال المحفوظ بعد اختبار ناجح يصبح متصل فوراً، والاتصالات المتصلة وحدها تجيب على الطلبات.

  3. تحقّق من البوابة وانسخ المفتاح

    يجب أن يقول سطر الحالة ● يعمل والخدمة: تعمل. افتح سيرفر ويب واضغط نسخ مفتاح API. على Linux: bytebridge status ثم bytebridge key show.

  4. شغّل النفق

    cloudflared tunnel --url http://127.0.0.1:8080

    لنفق باسم ثابت على نطاقك الخاص، راجع GATEWAY.md.

  5. تأكّد من المسار كاملاً

    لا يحتاج /health إلى مفتاح، فابدأ به:

    curl https://<your-hostname>/health

  6. استعلم

    curl -X POST https://<your-hostname>/query \
  -H "X-API-Key: <your key>" \
  -H "Content-Type: application/json" \
  -d '{ "database": "Sales", "sql": "SELECT ID, NAME FROM CUSTOMERS WHERE ID = @id", "parameters": { "id": 42 } }'

    أرسل القيم في parameters، ولا تدمجها في نص sql أبداً: تُربط القيم معاملاتٍ في قاعدة البيانات، فلا يمكن لقيمة أن تصبح SQL.

الـ API

يُرسل المفتاح في الترويسة X-API-Key، أو بصيغة Authorization: Bearer.

الطريقةالمسارالمفتاحماذا يفعل
GET/healthلايتحقق أن البوابة تعمل، لاختبار النفق. لا يعيد أي بيانات من قواعد البيانات.
GET/databasesنعمالاتصالات المُعدّة.
GET/statsالمفتاح فقطعدد الطلبات لكل اتصال، والإصدار العامل، وهل يوجد إصدار أحدث.
POST/queryنعمينفّذ SELECT أو WITH ويعيد الصفوف.
POST/executeنعميغيّر البيانات أو البنية، فقط عندما يكون السماح بالكتابة مفعّلاً، وإلا يعيد 403.

شكل الطلبات والردود، وتحويل الأنواع، ورموز الحالة، وحل المشكلات، كلها في مرجع الـ API وفي GATEWAY.md (بالإنكليزية).

سطر الأوامر

لا توجد نافذة على Linux، فتُدار كل الإعدادات بالأمر bytebridge. وعلى Windows Server Core يعمل ملف الخدمة التنفيذي أداةَ الإدارة نفسها: ByteBridge.Service.exe <command>. تسري التغييرات خلال ثوانٍ، دون إعادة تشغيل الخدمة.

bytebridge status
bytebridge db add --name Sales --server 127.0.0.1 --path /data/sales.fdb --user SYSDBA --password secret
bytebridge key show
bytebridge port 8080
الأمرماذا يفعل
statusيعرض حالة البوابة وقواعد البيانات.
on | offيشغّل البوابة أو يوقفها عن الاستماع.
port <number>يغيّر منفذ الاستماع.
key show | key newيعرض مفتاح API أو يستبدله.
lockout show|on|off|setحدّ المفاتيح الخاطئة من الجهة نفسها.
db list|add|enable|disable|removeإدارة اتصالات قواعد البيانات؛ ويختار --type firebird|postgresql المحرّك.
oauth show|set|on|off|edgeإعدادات تسجيل الدخول عبر Cloudflare Access.
enroll، claim، enrollment، sync-key، unenrollالاتصال بـ ByteBalanceTech للحصول على نفق، والتراجع عنه.
update [check]|status|on|offيبحث عن إصدار أحدث الآن، أو يعرض نتيجة آخر بحث، أو يشغّل البحث اليومي أو يوقفه. يبحث فقط، ولا يثبّت شيئاً أبداً.

يعرض bytebridge --help القائمة كاملة.

نموذج الأمان

يجعل النفقُ البوابةَ قابلة للوصول من الإنترنت العام، فعامل مفتاح API معاملة كلمة سر قاعدة البيانات.

  • كل المسارات عدا /health تتطلب المفتاح. يسري تبديله بزر مفتاح جديد خلال ثوانٍ، ويُرفض بعدها كل من يرسل المفتاح القديم.
  • لا تستمع البوابة إلا على 127.0.0.1، وتَرفض أي طلب يزيد جسمه على 1 MB.
  • يرفض /query كل ما ليس SELECT أو WITH، ويُبقي محرّك قاعدة البيانات معاملته للقراءة فقط. وتُرفض أيضاً العبارات التي تحرّك عدّاداً (GEN_ID بخطوة غير 0، وNEXT VALUE FOR، وnextval، وsetval).
  • ما دام السماح بالكتابة مفعّلاً، يستطيع كل من يملك المفتاح تغيير البيانات وحذفها وتغيير بنية قواعد بياناتك. اتركه متوقفاً إلا إن احتجته، وأوقفه بعد الانتهاء.
  • كل من يملك المفتاح يستطيع قراءة ما يستطيع مستخدم قاعدة البيانات في أي اتصال متصل قراءته. إن كانت البيانات حساسة، فضع Cloudflare Access أمام اسم النطاق أيضاً.
  • مجلد البيانات مقفل: C:\ProgramData\ByteBridge للمسؤولين وحساب الخدمة، و/var/lib/bytebridge لحساب الخدمة وحده. أما صورة الجهاز الكاملة (نسخة القرص أو لقطة الجهاز الافتراضي) فتحوي البيانات ومفتاحها معاً، فعاملها معاملة كلمات السر.

التفاصيل في مرجع الأمان؛ وللإبلاغ عن ثغرة راجع SECURITY.md.
