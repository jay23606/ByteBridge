ByteBridge

A small, authenticated HTTP API in front of your databases, so they can be reached from outside the machine through a tunnel such as Cloudflare Tunnel — without exposing the database port or touching the router.

On Windows it runs as a service with a desktop control panel; on Linux, as a systemd service you set up from the terminal. Add your database connections, turn the ones you want Online, and the gateway serves them as JSON over 127.0.0.1.

How it works

  1. Your appor browser
  2. HTTPS + X-API-Key
  3. Cloudflareedge
  4. outbound tunnel
  5. cloudflaredyour machine
  6. 127.0.0.1:8080
  7. ByteBridgethe gateway
  8. database port
  9. DatabaseFirebird or PostgreSQL

Nothing listens on your LAN and no inbound port is opened: cloudflared dials out to Cloudflare, and the gateway itself only ever binds to loopback.

Features

Runs as a service

A Windows service, ByteBridge, or a systemd unit, bytebridge. It starts with the machine and serves with nobody signed in, so closing the window does not take the gateway down.

Two database engines

Firebird 4 (default port 3050) and PostgreSQL (5432). Both are tested against a real server in CI.

Read-only by default

/query takes only SELECT or WITH, and runs it in a transaction the database engine itself holds read-only. Writing through /execute stays off until an administrator turns on Options → Allow writing.

An API key on every call

32 random bytes, generated on first run and compared in constant time. New Key rotates it without a restart, and a caller sending too many wrong keys is refused with 429 for a while.

Secrets encrypted at rest

Database passwords and the API key are encrypted with a key that never leaves the machine and is kept outside the data folder — DPAPI on Windows, an owner-only key file on Linux. A copy of the data folder alone opens nothing.

A log of every request

Every request, served or refused, is appended to the request log. The statement is written; bound parameter values never are.

Updates you approve

About once a day it asks GitHub for a newer release and shows a banner. Update now checks the installer against the release's checksums and starts it only once you agree. On Linux, apt does the updating.

Cloudflare Access, optionally

Put Cloudflare Access in front of the hostname so callers are authenticated at Cloudflare's edge first. With Cloudflare login set up in ByteBridge, a valid session from it is accepted in place of the key.

A tunnel made for you, optionally

Connect to ByteBalance in the window, or enroll on the command line, lets ByteBalanceTech make the tunnel. ByteBridge is a standalone product; this is an optional integration.

Install

Requires 64-bit Windows 8.1 or later, or a 64-bit Linux with systemd; and a Firebird 4 or PostgreSQL server for it to reach.

Windows

Grab an installer from the latest release. All of them are per-machine and ask for administrator rights once.

File.NETUse it when
…-x64-setup.exeincludedStart here. Normal desktop install.
…-x64.msiincludedGroup Policy, Intune, or a scripted rollout.
…-x64-framework-setup.exefetchedMuch smaller; Setup installs the runtime if the machine lacks it.
…-x64-framework.msirequiredScripted rollout where the runtime is managed separately.

Both .exe installers also offer to install cloudflared. Pointing it at a tunnel still needs your own token.

Silent install:

ByteBridge-<version>-x64-setup.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART
msiexec /i ByteBridge-<version>-x64.msi /quiet /norestart

Linux (Debian and Ubuntu)

Add the signed apt repository once; after that apt install and apt upgrade do the rest.

sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://kenanwahbeh.github.io/ByteBridge/bytebridge.asc | sudo tee /etc/apt/keyrings/bytebridge.asc >/dev/null
echo "deb [arch=amd64 signed-by=/etc/apt/keyrings/bytebridge.asc] https://kenanwahbeh.github.io/ByteBridge stable main" | sudo tee /etc/apt/sources.list.d/bytebridge.list
sudo apt update
sudo apt install bytebridge

The signing key's fingerprint is on the apt repository's page; compare it with gpg --show-keys /etc/apt/keyrings/bytebridge.asc.

Other distributions: each release also carries a linux-x64 tarball with install.sh, and the .deb itself, with checksums in SHA256SUMS-linux.txt. See the Linux guide.

Check where a file was built

Every release file carries a signed build attestation, which the GitHub CLI checks before you run anything:

gh attestation verify ByteBridge-<version>-x64-setup.exe --repo kenanwahbeh/ByteBridge

Quick start

Not a developer? The picture guide walks through the same steps with screenshots. In the app, Help → User Guide (or F1) opens it.

  1. Add a database

    Choose File → New Database…, fill in the server, port, user, password and database path or alias, and use Test Connection before saving. On Linux, use bytebridge db add.

  2. Check it is Online

    A connection saved after a successful test is Online straight away, and only Online connections answer requests.

  3. Check the gateway and copy the key

    The status line should read ● Answering — http://127.0.0.1:8080 · Service: running. Open Web Server and press Copy API Key. On Linux: bytebridge status and bytebridge key show.

  4. Start the tunnel

    cloudflared tunnel --url http://127.0.0.1:8080

    For a named tunnel with your own hostname, see GATEWAY.md.

  5. Confirm the whole path

    /health needs no key, so it is the first thing to try:

    curl https://<your-hostname>/health

  6. Query

    curl -X POST https://<your-hostname>/query \
  -H "X-API-Key: <your key>" \
  -H "Content-Type: application/json" \
  -d '{ "database": "Sales", "sql": "SELECT ID, NAME FROM CUSTOMERS WHERE ID = @id", "parameters": { "id": 42 } }'

    Send values in parameters, never concatenated into sql: they are bound as database parameters, so a value cannot become SQL.

The API

The key goes in X-API-Key, or as Authorization: Bearer.

MethodPathKeyWhat it does
GET/healthnoLiveness, to test the tunnel. Returns no data from any database.
GET/databasesyesThe configured connections.
GET/statskey onlyRequest counts per connection, the running version, and whether a newer release exists.
POST/queryyesRuns a SELECT / WITH and returns rows.
POST/executeyesChanges data or structure — only while Allow writing is on, otherwise 403.

Request and response shapes, the type mapping, status codes and troubleshooting are in the API reference and GATEWAY.md.

Command line

On Linux there is no window: everything is done with the bytebridge command. On Windows Server Core, the service executable doubles as the same admin tool: ByteBridge.Service.exe <command>. Changes apply within a few seconds, without restarting the service.

bytebridge status
bytebridge db add --name Sales --server 127.0.0.1 --path /data/sales.fdb --user SYSDBA --password secret
bytebridge key show
bytebridge port 8080
CommandWhat it does
statusShow the listener and the databases.
on | offWhether the gateway should listen.
port <number>Change the listening port.
key show | key newPrint the API key, or replace it.
lockout show|on|off|setThe limit on failed keys from one caller.
db list|add|enable|disable|removeManage database connections; --type firebird|postgresql picks the engine.
oauth show|set|on|off|edgeCloudflare Access login settings.
enroll, claim, enrollment, sync-key, unenrollConnecting to ByteBalanceTech for a tunnel, and undoing it.
update [check]|status|on|offLook for a newer release now, show the last result, or turn the daily check on or off. It only checks; it never installs anything.

bytebridge --help lists everything.

Security model

The tunnel makes the gateway reachable from the public internet, so treat the API key as a database credential.

  • Every endpoint except /health requires the key. Rotating it with New Key takes effect within a few seconds, and every client still sending the old one is refused from then on.
  • The listener binds to 127.0.0.1 only, and a request body over 1 MB is refused.
  • /query refuses anything that is not a SELECT or WITH, and the database engine holds its transaction read-only. Statements that move a sequence (GEN_ID with a step other than 0, NEXT VALUE FOR, nextval, setval) are refused as well.
  • While Allow writing is on, anyone holding the key can change and delete data and change the structure of your databases. Leave it off unless you need it, and turn it off again afterwards.
  • Anything holding the key can read whatever the database user of an Online connection can read. For sensitive data, put Cloudflare Access in front of the hostname as well.
  • The data folder is locked down: C:\ProgramData\ByteBridge to Administrators and the service account, /var/lib/bytebridge to the service account only. A full-machine image still holds both the data and its key, so treat disk clones and VM snapshots as credentials too.

The details are in the security reference; to report a vulnerability, see SECURITY.md.
